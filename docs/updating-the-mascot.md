# updating the mascot image

The mascot lives in two places, each serving a different purpose:

| path | tracked by git? | purpose |
| --- | --- | --- |
| `wip/*` | no (gitignored) | scratch space for source files, drafts, exports — anything not ready to publish |
| `assets/linkulino.gif` | yes | the canonical, full-resolution animation — referenced by the README (and rendered on the in-app About page) |
| `web/public/linkulino.gif` | yes | a downsized copy the SPA actually serves, as the header avatar and its hover lightbox |

`web/public/linkulino.gif` is **not** a symlink or a build step — it's a
separate file that has to be regenerated by hand whenever `assets/linkulino.gif`
changes. This doc is that process.

The favicon is a plain `🧮` emoji (a data-URI SVG in `web/index.html`), not an
image file — no regeneration needed there.

## steps

1. Drop the new animation wherever in `wip/` (e.g. `wip/linkulino_m.gif`) — anything goes here, it never gets committed.
2. Copy it over the published asset:
   ```bash
   cp wip/<your-file>.gif assets/linkulino.gif
   ```
3. Regenerate the web copy, downsized to keep the shipped bundle light. `sips`
   can't resize animated GIFs (it drops the animation), so use `gifsicle`
   (`brew install gifsicle`) instead:
   ```bash
   gifsicle -O3 --resize 320x320 --lossy=100 --colors 128 assets/linkulino.gif -o web/public/linkulino.gif
   ```
   `--resize 320x320` caps the longest edge at 320px (the app only ever shows
   it at avatar/lightbox size); `--lossy` and `--colors` trim the per-frame
   palette, which matters far more than resolution for GIF file size.
4. Commit both `assets/linkulino.gif` and `web/public/linkulino.gif` — they're
   independent files, so both need to be staged.

## why 320px

A source straight out of an AI image/animation tool can easily be 1024px and
15+MB — much too large to ship. 320px at a trimmed color count lands in the
low single-digit MB range, which is still sizeable for a GIF but tolerable
for a once-per-session header asset. If the mascot is ever shown larger
somewhere in the app, regenerate at a larger size for that one use rather
than bumping this shared copy — a bigger `web/public/linkulino.gif` costs
every page load.
