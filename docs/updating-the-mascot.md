# updating the mascot image

The mascot lives in three places, each serving a different purpose:

| path | tracked by git? | purpose |
| --- | --- | --- |
| `wip/*` | no (gitignored) | scratch space for source files, drafts, exports — anything not ready to publish |
| `assets/linkulino.png` | yes | the canonical, full-resolution image — referenced by the README (and rendered on the in-app About page) |
| `web/public/linkulino.png` | yes | a downsized copy the SPA actually serves, as the favicon and header avatar |

`web/public/linkulino.png` is **not** a symlink or a build step — it's a
separate file that has to be regenerated by hand whenever `assets/linkulino.png`
changes. This doc is that process.

## steps

1. Drop the new image wherever in `wip/` (e.g. `wip/linkulino_m.png`) — anything goes here, it never gets committed.
2. Copy it over the published asset:
   ```bash
   cp wip/<your-file>.png assets/linkulino.png
   ```
3. Regenerate the web copy, downsized to keep the shipped bundle light (the source is typically 2048px / 2–3MB; the app only ever displays it at favicon/avatar size):
   ```bash
   cp assets/linkulino.png web/public/linkulino.png
   sips -Z 512 web/public/linkulino.png --out web/public/linkulino.png
   ```
   `sips` is preinstalled on macOS. `-Z 512` resizes so the longest edge is
   512px, preserving aspect ratio. (On Linux, `convert -resize 512x512 in.png
   out.png` from ImageMagick does the same thing.)
4. Commit both `assets/linkulino.png` and `web/public/linkulino.png` — they're
   independent files, so both need to be staged.

## why 512px

Georgie's equivalent assets (favicon/avatar) sit in the same 90–290KB range at
similar dimensions, so this matches the existing precedent rather than being
an arbitrary choice. If the mascot is ever shown larger somewhere in the app,
regenerate at a larger size for that one use rather than bumping this shared
copy — a bigger `web/public/linkulino.png` costs every page load.
