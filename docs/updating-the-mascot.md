# updating the mascot image

The mascot lives in a few places, each serving a different purpose:

| path | tracked by git? | purpose |
| --- | --- | --- |
| `wip/*` | no (gitignored) | scratch space for source files, drafts, exports — **this is where the full-resolution original belongs** |
| `assets/linkulino.gif` | yes | the 320px animation referenced by the README (and rendered on the in-app About page) |
| `web/public/linkulino.gif` | yes | the same 320px animation, served by the SPA: the header avatar, its hover lightbox, and the large avatar on the signed-out screen |
| `assets/linkulino.png` | yes | the earlier static portrait, kept for reference — nothing links to it anymore |

**The full-resolution original is deliberately not in git.** A 1024px source is
15+MB, and git keeps every revision forever — a repo carrying two of those is
mostly mascot by weight, and GitHub would serve 15MB to every visitor who so
much as views the README. Keep the original in `wip/` (or wherever you archive
source art) and commit only the 320px derivatives.

The two tracked copies are byte-identical today, but they're independent files,
not a symlink or a build step — both have to be regenerated by hand. This doc
is that process.

The favicon is a plain `💰` emoji (a data-URI SVG in `web/index.html`), not an
image file — no regeneration needed there. (It's an emoji rather than a crop of
the mascot because a 320px animation makes a poor 16px icon. Note that not
every emoji works: `🖩` U+1F5A9, the "pocket calculator", has no colour glyph in
the common system emoji fonts and renders as an empty box.)

## steps

1. Drop the new animation wherever in `wip/` (e.g. `wip/linkulino_m.gif`) — anything goes here, it never gets committed. Keep it there: this is the archive copy of the full-res original.
2. Downsize it to keep both the repo and the shipped bundle light. `sips`
   can't resize animated GIFs (it drops the animation), so use `gifsicle`
   (`brew install gifsicle`) instead:
   ```bash
   gifsicle -O3 --resize 320x320 --lossy=100 --colors 128 wip/<your-file>.gif -o web/public/linkulino.gif
   ```
   `--resize 320x320` caps the longest edge at 320px (the app only ever shows
   it at avatar/lightbox size); `--lossy` and `--colors` trim the per-frame
   palette, which matters far more than resolution for GIF file size.
3. Copy that same downsized result to the README asset — resize from `wip/`,
   never commit the full-res file:
   ```bash
   cp web/public/linkulino.gif assets/linkulino.gif
   ```
4. Commit both `assets/linkulino.gif` and `web/public/linkulino.gif` — they're
   independent files, so both need to be staged.

## why 320px

A source straight out of an AI image/animation tool can easily be 1024px and
15+MB — much too large to ship. 320px at a trimmed color count lands in the
low single-digit MB range, which is still sizeable for a GIF but tolerable
for a once-per-session header asset. If the mascot is ever shown larger
somewhere in the app, regenerate at a larger size for that one use rather
than bumping this shared copy — a bigger `web/public/linkulino.gif` costs
every page load.
